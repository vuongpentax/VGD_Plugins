# Phase 0 — Enscape data findings

Source: user-provided, read-only inspector report from SketchUp 2024 (`24.0.484`), reviewed 2026-10-12. The SKP and report were not modified. Absolute paths are omitted here because the report contains machine-specific directories and model metadata.

## Observed storage

The report contains 4,948 attribute entries. Enscape-related material data is stored on SketchUp materials:

- `Enscape.Material` → `MaterialData`: XML serialized material properties.
- `Enscape.TextureData` → `RoughnessTextureData` / `HeightTextureData`: XML `SerializedEmbeddedTexture` records with `FilenameHint`, `ImageType`, `Content`, and `Base64Content`.
- `Enscape.EmbeddedSettings` on the model contains `SkyboxFile` values. These are environment/skybox references, not material maps.

Within `MaterialData`, 102 non-empty `<Filepath>` values were found:

| XML channel node | References |
| --- | ---: |
| `DiffuseTexture` | 30 |
| `BumpTexture` | 32 |
| `RoughnessTexture` | 35 |
| `MaskTexture` | 5 |

The XML also includes `BumpMapType`, `NormalMapIntensity`, roughness, opacity, emissive, metallic, and other material properties. `BumpTexture` therefore needs its `BumpMapType` interpreted before naming a resource specifically as a normal map.

## Embedded image evidence

There are 41 `Enscape.TextureData` records: 29 roughness and 12 height. All 41 contain Base64 data that decodes to a recognized image signature (38 JPEG, 3 PNG). Their `FilenameHint` values are absolute paths. In this sample, 38 hints match at least one `MaterialData` filepath; 3 do not match those material entries.

All 102 `MaterialData` filepath values were missing on the machine where the report was generated. The records span absolute, rooted, and filename-only forms, so matching cannot assume every stored filepath is absolute.

## Safety conclusion

Readable: diffuse, bump, roughness, mask file references; embedded roughness and height image payloads; and a model-level skybox path.

The report establishes where relevant values live, but it does not prove that changing `MaterialData/Filepath` or `FilenameHint` is sufficient for Enscape to reload the corresponding map. No channel is marked safe to relink yet. The next validation must use a disposable copy of a model and confirm the changed resource in Enscape Material Editor before implementing any Enscape write adapter.

## Inspector correction

The report's original `asset_candidates` field was generated by a broad scan over serialized XML and can contain false positives. VGD_Package 0.1.2 parses XML and JSON values before extracting path candidates. The raw report remains useful for this analysis; re-export with 0.1.2 for clean candidate lists.
